# 管理后台功能生效与使用体验核对

## 本批结论

优先检查设置页从保存到实际消费的链路，以及移动导航。不是所有能保存的字段都能改变官网；本批修复明确失效的配置、缓存刷新和错误提示，并标明未接入项。其他模块结合既有回归和本轮源码检查记录证据，不声称所有按钮已逐一完成真实环境验收。

| 后台功能 | 当前实际效果与依据 | 本批处理 |
| --- | --- | --- |
| Google 站点验证码 | 原先只写入数据库，官网只读环境变量；本轮真实本地后台保存→官网 HTML 验证通过 | 接入公开白名单和服务端 metadata，明确空值移除标签 |
| GA4 / Clarity | 运行时公开设置被同意管理组件消费；完整回归中的同意、撤回、重新加载用例通过 | 补充访客同意后生效和填写格式说明 |
| 联系邮箱 | 联系页和隐私政策读取；不是全站所有邮箱文字的统一替换 | 标明消费位置和留空回退默认值 |
| 电话 / WhatsApp / 地址 | 联系页读取；地址文字变化不会改变地图坐标 | 标明范围，避免误解为整个网站和地图一起改变 |
| site_name / company_name / company_logo / company_fax / company_linkedin / company_youtube / company_facebook | 当前官网未消费这些历史配置 | 保留值，只读显示“未接入官网”；不删除数据、不擅自替换品牌信息 |
| SMTP 普通配置 | 数据库非空值覆盖部署环境，空值回退环境 | 修正“留空停发”的误导说明，保留实际配置优先级 |
| SMTP 测试 | 后端成功返回 data:null，客户端解包后原页面读取 msg 会抛错 | 接受 null 并正确显示成功；浏览器拦截测试，不发送真实外部邮件 |
| 公开设置刷新 | 原先只删除 Redis 缓存，官网 ISR 缓存未同步清理；事务提交前失效还可能回填旧值 | 复用持久化任务，在事务提交后刷新 Redis 和官网，失败保留重试任务 |
| 移动导航 | 点击目的页面后抽屉不收起；768px JS 断点与 1024px CSS 断点不一致 | 统一断点并在点击菜单后收起；390px 和 820px 浏览器验证通过 |
| 新闻管理 / 排序 / 批量操作 | 既有管理员分页、草稿/定时显示、部分失败重试测试本轮继续通过 | 保留已修复实现 |
| 询盘管理 | 真实提交后可在后台看到；详情加载失败和跨记录竞态回归通过 | 保留第二轮修改；时间线追加的部分失败仍列后续 |
| 私有预览 | 既有签名预览及未发布隔离链路回归通过 | 未扩展预览按钮在非标准域名、浏览器弹窗拦截下的行为 |
| 用户 / 账号 / 分类 / 媒体 / 审计 | 后端全套测试覆盖相关权限与业务；不是每个后台页面都完成独立 UI 验收 | 后续继续按实际点击路径核查，未强行改动 |

## 实现边界

- 没有新增数据库字段、依赖或设置写入 API 字段。公开设置响应增加非敏感的 google_verification，所有本项目调用方已检查；敏感 SMTP 授权码仍不公开。
- 复用现有 content_cache 任务处理设置失效。单项与批量写入都在提交后执行缓存任务；失败沿用任务重试策略。生产需要前后端同步发布，以识别 public-settings 标签。
- 官网根 metadata 增加有缓存的公开设置读取，构建仍生成静态页面；相关页面的再验证周期受 300 秒设置缓存影响。没有宣称改善加载耗时。
- 后台留空验证码表示明确删除；API 没有该配置或读取失败时兼容环境变量。已打开页面仍需要重新加载才能核对新内容。
- 未接入项采用明确只读状态，保留后续接入空间，没有虚构其用途或让用户继续无效编辑。
