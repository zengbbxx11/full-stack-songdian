# 产品与新闻管理专项检查

## 结论与行为矩阵

本轮使用真实本地后台、后端、官网生产构建及隔离测试数据。重点验证了状态切换后的可管理性，而非仅模拟列表响应。

| 操作 | 后台结果 | 官网结果 | 验证 |
| --- | --- | --- | --- |
| 表单新建并发布产品/新闻 | 创建成功，返回列表可找到 | 公开 API 可读取 | 两类内容真实浏览器通过 |
| 发布改草稿 | 列表显示草稿；可重新编辑，标题和正文保留 | 公开详情不可读，搜索无结果，sitemap 移除，先前缓存页面返回 noindex 边界 | 两类内容真实浏览器及后端回归通过 |
| 草稿预览 | 编辑页“打开预览”可用 | 签名预览页显示保存内容，普通网址不公开 | 两类内容实际打开新窗口通过 |
| 定时发布 | 状态和时间保存、重新打开回显 | 到期前不公开；后端既有调度器负责到期发布 | 亚洲/上海 08:30 写入 UTC 00:30 验证通过；未在浏览器等待七天后到期 |
| 恢复初始发布版本 | 新版本记录，编辑页回显已发布 | 恢复版本自身的发布状态 | 两类内容点击恢复通过 |
| 删除 | 列表移除 | 公开详情不可读 | 两类内容点击确认删除通过 |
| 产品图库 / 规格 | 添加后刷新仍保留，删除后移除 | 沿用已有接口 | 真实文件上传、图库/规格增删通过 |

## 发现与修复

1. 后台新闻列表调用 GET `/admin/news`，后端缺少该路由，真实请求 405。补齐鉴权管理员分页路由，公开列表仍强制 PUBLISHED。此前的列表模拟测试未发现缺口，本轮增加真实链路和后端路由测试，修正之前对新闻列表可用性的判断。
2. 新闻创建接口必须有 category_id，而表单没有分类选择和提交，导致创建失败。新增真实分类选择和数字 ID 提交，编辑回显当前分类；分类按全量分页获取。产品分类也改为完整分页并明确必选。
3. 保存后返回列表沿用旧 SWR 快照，状态看起来没有变化。保存和删除后清理并重新验证相关后台列表缓存；必须执行重新验证，不能只清空，因为 Next 会保留导航页面实例。
4. 编辑表单没有可靠的加载失败边界，且依赖整个 Toast context 会在通知变化时重新加载，覆盖编辑。改为稳定的通知方法依赖、忽略过期响应、按记录重建表单实例，加载失败显示重试且不允许空表单保存。
5. 直接截取 UTC 时间给 datetime-local 会错误解释时区。共享时间转换函数按设备本地时区显示，保存为带时区 ISO；定时状态必须填写未来时间。
6. 预览等待请求后才 window.open，可能被弹窗拦截。点击时先打开窗口，失败关闭；始终保留可手动打开的生成链接。提供可选官网地址配置。
7. 版本历史读取失败显示成“保存后将生成版本”，误导用户。改用 SWR 显示加载、错误和重试，删除既有 effect 依赖禁用注释。
8. 复制页展示源产品图库/规格但没有新 ID，添加删除按钮无效。明确复制范围，隐藏无效编辑入口，提示保存后添加；已有产品提示图库/规格立即保存，不受取消影响。
9. 产品 SEO 标记只判断标题，导致仅填写描述时误报“未设置”。现在任一 SEO 字段有值即显示已设置。修正默认描述来源说明，移除重复追加品牌的标题示例，为 SEO 输入提供可访问名称，保存时锁定快速编辑内容并避免遮罩关闭。

## 产品 SEO 字段实际效果

- 产品表单填写自定义标题、描述后，数据库与管理员列表可读回；官网实际页面 title、description、Open Graph 标题/描述、Twitter 描述均使用自定义值，正文 H1 仍为产品名称。
- 浏览器通过列表 SEO 快速编辑清空标题、只修改描述后，官网标题回退产品名，描述更新；无需重新构建。仅描述的状态显示“已设置”。
- 再清空描述后，官网恢复由产品名、公司介绍和简介拼接并截取的默认描述，列表显示“未设置”。后端 clean_text 将清空值规范化为空字符串，遵循现有约定。
- 官网页面 title 会自动追加品牌；填写时无需再追加。分享标题使用字段本身。这两个字段已被使用，本轮没有重新实现现有 SEO 渲染链路，也不将标签生效等同于排名提升。

## 保留与限制

- 不更改分类体系、数据库结构、公开 API 的发布状态限制。新增缺失的管理员 GET 路由，与已存在的前端调用和分页信封一致，要求 news:read 权限。
- 草稿可由有权限的管理员查看，并不表示可用普通官网网址访问。预览只展示最后保存内容，未保存的编辑不在预览中。
- 恢复已发布版本会恢复为已发布，仍遵循后端发布权限；不是仅恢复文字而保持草稿。确认提示已明确发布状态一同恢复及未保存编辑丢失。
- 后端删除为既有软删除，按 ID 的管理员接口可能保留读取历史的能力；没有擅自改为物理删除。
- 复制不是完整复制图库/规格，本轮使范围真实可见，没有新增跨多个 API 的不完整复制事务。
- 本轮没有穷举每种富文本格式、所有上传类型、真实 SMTP 或每种浏览器。使用本机 Edge；生产 Redis 失效和部署连通性仍需 CI/部署验证。
- 根 metadata 与设置页等上一批工作树修改保留。本轮不创建 Git commit。
