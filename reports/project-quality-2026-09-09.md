# 项目质量增量优化记录

范围：官网、管理后台、后端交互；保持数据库结构、API contract、分类体系与业务事实。

## 基线

- 工作树初始干净。
- 官网 ESLint、后台 ESLint、后端 Ruff 均通过。
- Windows PowerShell 因 CET 兼容性错误无法启动，使用 cmd 与 Node/Python 执行检查。

## 阶段一：新闻与 SEO

已完成：区分新闻不存在与服务故障；使用 Next.js 16.3 retry 重新获取失败内容；保留机器可读发布日期，省略未知修改日期；sitemap 运行时完整获取 URL，产品使用真实更新时间；独立新闻辅助请求并行；修复 CI mock 对带查询参数列表请求的错误匹配。

验证：官网 ESLint、verify:seo、4 个新增数据回归用例、Next.js 生产构建（含 TypeScript）通过。后端基线 pytest：121 passed，6 条依赖弃用警告。浏览器综合回归安排在阶段四。

取舍：sitemap 请求时读取后端（后端现有 Redis 缓存仍生效），避免镜像在 API 缺席时保存缺少动态内容的站点地图。没有修改数据库或 API 字段。Next.js 流式响应已开始后，notFound 可能仍为 HTTP 200，但会输出标准 noindex 与 404 边界。

## 阶段二：询盘提交

已完成：相同提交内容在失败重试时复用业务单号；成功或内容变化后生成新单号；前端 trim 与字段长度对齐后端，数量与留言合计不超过 2,000 字符；原生单选框支持方向键；错误与字段通过 ARIA 关联，隐藏的可选字段出现错误时展开，发送中禁止编辑。

验证：ESLint、生产构建与 TypeScript 通过；Edge 无头浏览器运行 3 个回归用例通过，覆盖响应丢失后的重试、内容变更、新询盘、长度边界、键盘选择和隐藏字段错误。首次 UI 回归发现 sr-only 输入的点击区域问题，已改为覆盖完整胶囊的透明原生输入，并复测通过。

边界：幂等键保留在当前表单实例中，不向浏览器持久存储个人资料；刷新整个页面后的恢复未在本阶段扩展。

## 阶段三：后台操作与会话可靠性

已完成：并发及迟到的 401 共享一次刷新；退出等待刷新，临时故障保留错误；生产缺少 JWT 密钥时拒绝认证，路由校验 access scope，失效会话登录避免跳转循环。新闻管理读取全部管理员分页，草稿和定时文章正常出现；筛选排序保留隐藏项位置，后台刷新不覆盖排序草稿。批量写入限制并发、等待全部结果、保留失败项；统计卡片复用现有聚合接口。原生确认对话框管理焦点、等待异步操作并阻止重复确认；登录标签与密码可见性按钮支持键盘和辅助技术。

边界：批量写入仍使用现有单项 API，不能提供数据库级全批事务；部分失败会明确提示并支持重试或取消后重新读取。刷新协调限于当前页面，不包含跨标签页锁。

## 阶段四：地图、响应式与综合回归

已完成：地图接近视口才挂载及请求瓦片，保留固定占位、手动加载与失败重试；弹窗地址使用文本节点，消除配置值拼接 HTML 的注入入口。服务端设置请求遵循内部 API 地址。询盘输入框增至 44px 触控高度，保持既有视觉风格。

响应式检查覆盖 390、768、1440px 下的首页、产品、新闻、About、Solutions、FAQ、Contact、Search，检查页面横向溢出并保存首页和联系页截图；后台产品批量操作在 390px 验证。地图测试确认进入视口前没有瓦片请求，进入后才请求。使用隔离 SQLite 数据库及上传目录，SMTP 关闭，没有访问生产数据库或发送邮件。
