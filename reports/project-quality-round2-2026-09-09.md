# 第二轮质量优化：搜索与询盘编辑的请求竞态

## 范围与依据

沿用此前获批的增量优化范围，保留上一轮工作树。此次只修改官网即时搜索和后台询盘跟进编辑，新增针对延迟响应的回归测试；不更改数据库、API contract、产品分类、状态流转规则和品牌视觉，不创建 Git commit。

## 官网即时搜索

- 原请求编号到下一次搜索真正发出时才更新，因此清空或改词后的防抖窗口内，旧响应仍可回填结果。现在输入变化立即使旧请求失效，清理旧建议，卸载时也使响应失效。
- 加载中的旧建议不再参与键盘选择；Escape 清理选中状态，Enter 只使用当前可见且有效的建议，否则提交当前关键词。
- 初次 ArrowUp 正确选择最后一项；列表和选项 ID 使用组件实例 ID，辅助技术引用仅在对应元素存在时输出。
- 删除 2.5 秒自动隐藏错误的定时器，避免服务故障变成“没有产品”。保留错误并提供重试入口，再次聚焦可以展开当前状态。
- 浏览器回归发现原生 search 输入按 Escape 会清空关键词；已阻止该默认行为，使 Escape 只关闭建议框。

## 后台询盘跟进

- 原弹窗先填空备注、空国家和默认状态，详情请求失败被吞掉，仍可保存。这可能覆盖已有信息。现在沿用列表中的状态和国家作为加载显示，完整详情成功前禁用编辑与保存，失败显示错误并允许重试。
- 原先快速关闭 A 再打开 B，A 的迟到响应可能覆盖 B 的字段。现在每次打开和关闭都更新请求编号，只有当前请求可以写回字段、错误和加载状态。
- 保存期间禁用字段；补齐标签关联，备注输入限制为后端已有的 1,000 字符。

## 设计取舍与后续

请求归属在用户改变编辑目标时立即更新，而不是等下一次请求发出。保留现有 300ms 防抖和 API 客户端，未新增通用状态机或依赖。旧请求仍可能在网络上完成，但不能再更改当前界面；没有声称此次减少服务器请求量。

尚未扩展跨标签页会话协调或批量事务。询盘的状态保存与跟进时间线追加仍是两个现有请求，追加失败的反馈与恢复值得后续独立处理；本轮没有把它们改成新 API。此次没有直接的 SEO metadata 修改，既有 SEO 检查仍需通过。
