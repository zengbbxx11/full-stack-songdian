# 分类和 sitemap 缓存更新问题（2026-09-22）

## 定位证据
- 新建分类后，后台公开接口立即包含该分类，但官网第一次请求返回默认标题；后续请求或显式刷新恢复。
- 自动刷新接口实际收到正确的 tags / paths，HTTP 200，非参数解析或缺失失效标签。
- 当前 Next.js 16.3.4 内部 file-system-cache 使用 Date.now() 记录失效时间，areTagsExpired 使用 performance.timeOrigin + performance.now() 判断失效时间是否已经到达。
- 运行中的官网开发进程测得两套时钟差值约 3514.8ms。立即过期的时间在另一套时钟上仍位于未来，因此只触发 stale 后台更新，第一次请求可能仍返回旧缓存。
- 仅重启官网开发进程后，原样运行分类与 sitemap 相关 10 条测试全部通过。

## 处理
- 官网已恢复端口 3000 的后台静默开发模式；没有重启后台或数据库。
- 临时诊断日志、备份已清理。未修改 Next.js 内部源码、数据库、分类业务或降低原断言要求。
- 首页布局测试先拒绝 Cookie 并等待横幅隐藏，再测量轮播按钮；解决导航因横幅状态切换而在测量期间消失的竞态。
- 本次改动 lint / TypeScript 通过。完整 117 条 E2E 复跑结果见 cache-fix-full-e2e.json。

## 局限
这是本地运行状态恢复，不是对 Next.js 时钟实现的永久补丁。机器休眠、系统校时等情形可能再次造成偏移；如再次出现“发布后的第一次访问旧数据”，应检查运行进程时钟并重启官网服务，后续框架升级需确认此逻辑使用一致时钟。
- 为避免真实邮件，仍排除缺少清理步骤的真实询盘提交用例，模拟接口询盘测试正常覆盖。
